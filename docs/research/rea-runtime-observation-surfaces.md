# REA runtime observation surfaces: authority, declaration, and safety rails

Source checkout read: `/tmp/claude-1000/-home-cukin-agentic-anything/65f00ee4-6743-473f-85fc-7ebf788d62a2/scratchpad/rea-src` (rea-agents 6.8.0, `package.json`). Paths below are relative to that checkout. OBSERVED = read in source/docs. INFER = my interpretation.

## Summary

- REA exposes a graded ladder of runtime authority and keeps each rung in a **separate provider** with its own tool name: (1) attach-and-listen (CDP page capture, V8 Inspector discovery, Electron file-page inspection), (2) attach-and-instrument-passively (precise coverage, listener enumeration), (3) launch-or-connect-and-drive a browser (Playwright scenarios), (4) launch-and-hook an Electron app (preload via `-r`), (5) launch a process in a PTY and script its stdin/resize/signals (process capture), (6) spawn/attach plus inject caller JS (Frida), (7) unrestricted debugger console (GDB MI, Rizin). OBSERVED: `docs/browser-observation.md` "Provider authorities", `src/contracts/toolEffects.ts`.
- Authority is declared to the agent through a **closed effect vocabulary** per tool: `mutatesTarget, mutatesSession, writesFilesystem, launchesProcess, accessesNetwork, changesUiState, mayDiscardData, executesForeignCode, mutatesDevice, idempotent` (`src/contracts/toolEffects.ts:1-21`). MCP hints `readOnlyHint/destructiveHint/idempotentHint/openWorldHint` are **derived from those flags, never hand-set** (`toolEffects.ts:765-786`).
- REA states annotations are **hints, not authorization controls**, and that it has **no permission grant step or per-call approval flag**; the request itself defines the operation, and confirmation UI is delegated to the MCP client (`docs/mcp-contracts.md` "Request scope and local effects", lines ~1235-1258).
- Passive surfaces are hard-bounded to a tiny CDP command set: V8 Inspector sends exactly `Runtime.enable` + `Debugger.enable` (`src/inspector/V8InspectorProvider.ts:186,408-409`); web page capture never exposes `Runtime.evaluate`, WebMCP invoke, navigation, input, downloads, page/browser close (`docs/browser-observation.md` "Non-goals and threat model"). The one `Runtime.evaluate` in the browser tree is the scenario service-worker policy owner running its own restoration script (`src/browser/PlaywrightScenarioServiceWorkers.ts:317`).
- Endpoint admission is strict: literal loopback (`127.0.0.1`/`[::1]`) with explicit port only; `localhost`, LAN, HTTPS, `wss:`, credentials, implicit ports all rejected; targets another debugger marks `attached: true` are refused rather than displaced (`docs/browser-observation.md` "Request boundary", `src/browser/CdpAuthorizedTarget.ts:8-50`, `docs/javascript-runtime-observation.md`).
- "Active hook" (Electron) = a CommonJS preload injected via `-r scripts/electron-active-hook.cjs` into the app main process, launched through Playwright `_electron.launch`. It monkey-patches Electron/Node APIs to **record value-free shapes** of IPC and to **block** external effects while leaving the app otherwise running (`scripts/electron-active-hook-boundaries.cjs`, `scripts/electron-active-hook.cjs:1303-1340`).
- Process-lifecycle ownership is the recurring safety rail: owned processes get a `REA_PROCESS_RUN_ID` env token; signals are sent only to a process group whose leader carries that token after start-identity re-verification, and a mismatch is recorded `unverified` rather than escalated to a bare PID kill (`src/process/ProviderProcess.ts:281`, `docs/process-capture.md` "Finalization interval", `src/process/ProcessOwnershipObservation.ts:1563`).
- Frida and the native debuggers invert "never kill" in opposite directions: Frida never kills and resumes a paused spawn only after instrumentation is confirmed released (`src/frida/FridaInstrumentationManager.ts:743-800`); GDB/Rizin close paths detach the inferior and refuse to close when detach cannot be proven (`src/gdb/GdbSessionManager.ts:1934-2007`, `src/rizin/RizinDebugSessionManager.ts:1246-1315`).
- Data minimization is a first-class contract: value-free JSON "shapes", redacted storage, credential headers nulled, URL userinfo stripped, declared secrets replaced by `[REDACTED:...]` markers, screenshots withheld when secrets are in play, Frida auth tokens excluded from Evidence (`docs/browser-observation.md` "Data minimization", `src/browser/BrowserScenarioSecrets.ts`, `src/frida/FridaInstrumentationManager.ts:1059-1160`).
- Every surface returns "Evidence" with explicit `complete/partial/attach_limited/truncated` coverage and a `partial_observation` on failure; absence is never treated as proof. Fixed byte/time budgets are named in the result and typically "have no runtime override".

## How it works (by surface)

### 1. CDP page observation (`src/browser/Cdp*`, `docs/browser-observation.md`)
- Tools: `list_browser_targets`, `inspect_web_page`, `analyze_web_bundle`, `observe_web_session`, `discover_webmcp_tools`, `capture_web_screenshot`, `compare_web_*`. Effects for most = `browserEvidence` = `{mutatesSession, accessesNetwork}` only (`toolEffects.ts:645-655`); `analyze_web_bundle` adds `launchesProcess, writesFilesystem` (owned analysis worker, not target code).
- Authority: **attach-only** to a user-started Chrome launched with `--remote-debugging-port`; "REA does not launch, own, or terminate this browser." Passive session enables `Page.enable, Network.enable, Performance.enable, Page.setLifecycleEventsEnabled`, plus `Runtime/Debugger` and `DOMSnapshot.captureSnapshot`/`Page.getResourceTree` for script/DOM facts (grep of `src/browser/CdpObservationSession.ts`).
- Target admission: `authorizeCdpTarget` requires `type === "page"`, an HTTP(S) origin, and membership in `allowed_origins` (default = page's current origin) (`CdpAuthorizedTarget.ts:8-50`). A main-frame origin boundary is rechecked before enabling domains, before document capture, and after; a navigation mid-capture discards the result as `target_changed`.
- Non-goals: no generic CDP passthrough, no `Runtime.evaluate`, no `WebMCP.invokeTool`, no navigation/input/downloads/close. Cleanup disables only the domains it enabled, detaches, closes only its own socket.
- Honest side effects: enabling `Debugger` lets a page `debugger` statement pause (REA does not `setSkipAllPauses` or resume); Chromium may clear another client's `navigator.platform` emulation on disconnect (issue #4089).
- Budgets: 64 MiB per CDP message, 8 MiB retained observation, 32 MiB script source, 10 s discovery deadline, `command_timeout_ms` default 20000, 5000 ms cleanup grace; most "no runtime override".

### 2. Website runtime attribution (`src/browser/execution/`, `docs/web-runtime.md`)
- `observe_web_execution`: enables `Page, Runtime, Debugger, Network, Profiler`, then `Profiler.startPreciseCoverage({callCount:true, detailed:true, allowTriggeredUpdates:false})`, takes one resetting sample, `stopPreciseCoverage` (`src/browser/execution/CdpExecutionCapture.ts:27-37,75,182`). Declared `mutatesTarget, mayDiscardData, idempotent:false` because precise coverage resets counters and suppresses JIT optimization: "This changes timing/JIT behavior." Doc: "The operation itself selects instrumentation; no extra approval flag is needed."
- `inspect_web_event_listeners`: `DOM.querySelector` + `DOMDebugger.getEventListeners` (`CdpListenerSelector.ts:12`, `CdpEventListeners.ts:58`); "never invokes a listener or dispatches an event." Effects = `browserEvidence`.
- Both use an MCP progress "armed" notification so a human/agent triggers the behavior externally; REA does not click.

### 3. V8 Inspector passive discovery (`src/inspector/`, `docs/javascript-runtime-observation.md`)
- `list_javascript_runtime_targets` / `observe_javascript_runtime`. Provider comment: "Attach-only provider; sends only Runtime.enable and Debugger.enable" (`V8InspectorProvider.ts:186`). Retains only `Debugger.scriptParsed/scriptFailedToParse` and `Runtime.executionContext*` (`:638-700`).
- Never sends `Runtime.runIfWaitingForDebugger`: an `--inspect-brk` target stays paused and the caller is told to resume it with their own debugger.
- Role (`node`, `electron-main`, `electron-preload`, `electron-renderer`) is caller-declared and recorded as `caller-declared-unverified`; Inspector cannot authenticate PID or role.
- `V8InspectorAdmission` serializes close vs. active operations and retries pending transport cleanup (`V8InspectorProvider.ts:60-120`).

### 4. Electron (`src/electron/`, `src/browser/PlaywrightElectronActive*`, `scripts/electron-active-hook*.cjs`, `docs/electron-observation.md`)
Three distinct authorities, three tool groups:
- `inspect_electron_fuses`: static read of the fuse wire in the binary; "does not launch the app, modify fuse bytes, or use the network" (`docs/electron-fuses.md`). Effects = `evidence`.
- `list_electron_targets` / `inspect_electron_page`: passive CDP against a running Electron with a debugging port; only hostless `file://` pages resolving to regular files (including inside `app.asar`) are admitted (`src/browser/ElectronFileScope.ts`). "Inspection does not retain DOM values, execute renderer code, navigate, click, invoke Electron IPC, close a target, or terminate the application."
- `capture_electron_scenario`: **active**. Effects = full destructive set incl. `executesForeignCode, changesUiState, mayDiscardData` (`toolEffects.ts:669-680`).

What the active hook is and what authority it takes:
- `PlaywrightElectronActiveProvider.ts:158-176` launches `_electron.launch({executablePath, cwd:root, args:["-r", hookPath, application, ...input.args], env})`. Playwright prepends `--inspect=0 --remote-debugging-port=0`. Env is an allowlist (`HOME, LANG, PATH, TMP, TMPDIR, USER, DISPLAY, XAUTHORITY, WAYLAND_DISPLAY`, plus a Windows set) plus the run token; `NODE_OPTIONS` is excluded (`:390-415`).
- The hook (`scripts/electron-active-hook.cjs`) verifies argv matches Playwright's prefix and a SHA-256 handoff, then rewrites `process.argv` so the app sees only its own arguments; a mismatch leaves argv untouched and records `hook_conflict` (`:1250-1300`). It captures native builtins before app code can replace them (`:1-30`), then patches: `app` emitter; `ipcMain.on/once/handle/off/removeAllListeners`; `ipcRenderer.send/sendSync/invoke/postMessage`; `contextBridge.expose*`; `BrowserWindow` creation and `webContents.loadURL/loadFile/loadDataURL`, `webContents.send/postMessage`, `setWindowOpenHandler`; `utilityProcess.fork`; `shell.*`; `session.*`; `app.relaunch/...`; `process.dlopen`; `child_process.spawn/fork/exec/execFile`; and `process.emit` for rejection monitoring (`:1303-1340`).
- Blocking policy (`electron-active-hook-boundaries.cjs`): downloads cancelled; permission request/check handlers always deny; certificate verify always fails (-2); window-open handler forced to `deny`; `shell.openExternal/openPath/trashItem` reject, `showItemInFolder` returns undefined, `writeShortcutLink` returns false (`blockedShellResults`); `app.setAsDefaultProtocolClient/moveToApplicationsFolder` return false, `relaunch/setLoginItemSettings` return undefined; `loadURL` allowed only for `file:/data:/about:` or `http(s)` to loopback (`electron-active-hook.cjs:174-186`); `will-navigate`/`will-redirect` to external URLs blocked at event level (`:1167-1171`). Observed-but-NOT-blocked: `child_process.*`, `utilityProcess.fork`, `process.dlopen` (records addon SHA-256 when <= 16 MiB). INFER: the hook contains a desktop app to loopback + no external shell, but does not prevent the app from spawning subprocesses or loading native addons.
- Retention: `shape()` returns only `string|number|boolean|object|array|function|nested` at depth <= 2 (`:78-100`); 16 MiB budget with per-family drop counters; snapshot exposed via `globalThis.__reaElectronActiveSnapshot`, read by Playwright `application.evaluate`. "Payload values are never retained."
- Scenario actions: `click`, `wait`, `renderer-reload`, `renderer-crash` (`webContents.forcefullyCrashRenderer()`), deep-link via `app.emit("open-url"|"second-instance")` (`PlaywrightElectronActiveActions.ts:263-370`) -- synthetic controls. Doc: "not a passive CDP observation"; "lifecycle ownership does not make it a sandbox."
- Prerequisite gate: if `EnableNodeCliInspectArguments` fuse is disabled, the scenario fails before launch with `unsupported_target` and points to passive inspection. INFER: REA declines to work around vendor hardening -- relevant to the DRM/security-control boundary.

### 5. Playwright browser scenarios (`src/browser/PlaywrightScenario*`, `docs/browser-scenario-contract.md`)
- This is REA **driving a browser**, but through a declarative, closed action vocabulary: `click, fill, goto, press, request, select_option, wait_for, wait_for_timeout` (OBSERVED via `z.literal` grep, `src/domain/browserScenarioValues.ts`). No arbitrary JS evaluation of app code, no free-form CDP.
- Two modes: `launch` (caller-named executable, provider-owned temp profile deleted on cleanup, `headless` default true) and `connect` (loopback CDP endpoint; REA disconnects, never closes the external browser). `PlaywrightExecutionBoundary.ts` enforces per-op deadline and cancellation.
- `request` step: one `fetch` from the page main world to the start origin only; follows no redirects; header values from literals, declared secrets, cookies (HttpOnly included), localStorage, or saved response values. Doc: "the only action that changes application state without a user gesture, so run scenarios with write requests only against an instance whose data you may change."
- Secrets: declared via env-var names; resolved values replaced by `[REDACTED:<id>]` in durable output; page-derived values >= 8 chars redacted forward from read time; screenshots **withheld** whenever any secret could be in pixels (`BrowserScenarioSecrets.ts:26-28`).
- Service workers blocked by default via CDP debugger instrumentation that resumes only its own seed-script pauses; policy restoration uses `Runtime.evaluate` of REA's own script (`PlaywrightScenarioServiceWorkers.ts:300-330`).
- Budgets: 10,000 events, 16 MiB, 1,024 transactions, 64 KiB body per phase; 16 concurrent reads, 5 s per read, 30 s cleanup confirmation (`PlaywrightExecutionBoundary.ts:7,12`). Abrupt SIGKILL of REA can orphan profiles (issue #4659), documented not hidden.
- Effects: full destructive set (`toolEffects.ts:656-668`).

### 6. Frida (`src/frida/`, `src/composition/frida.ts`, `docs/frida-instrumentation.md`)
- Tools: `list_frida_devices`, `list_frida_processes`, `start_frida_session` (`mode: attach|spawn`), `load_frida_script`, `resume_frida_session`, `unload_frida_script`, `frida_session_status`, `close_frida_session`, one-shot CLI `instrument-with-frida`. `frida` is an optional dependency dynamically imported only when a Frida op runs (`FridaInstrumentationManager.ts:152`; `composition/frida.ts`). REA does not install Frida server on a target.
- Attach/spawn: `device.spawn(program,{argv})` then `device.attach(pid)` (`:317-336`). Spawned targets start paused; `resume_frida_session` is admitted only for a `spawn` session, only once, and refused while script cleanup is incomplete (`:582-626`).
- Scripts: caller-authored JS, inline or file; source is NOT stored in Evidence, only path + SHA-256 (`:419-470`). Doc: "Frida scripts execute inside the selected target with that process's memory, filesystem, and network authority."
- Never-kill: close unloads scripts, detaches, and if a spawn is still paused resumes it only after detach confirms release; if both cleanup paths fail the target stays paused and the error is retained (`:743-800`, `:912-930`). No `kill` call exists in the manager.
- Message caps (`fridaCaptureLimits.ts`): 16 MiB session, 128 KiB metadata, 4 KiB type, 32 KiB text, 250k JSON nodes, depth 64; binary data capped. Limitations are reported only for caps REA itself hit (`collectOwnedCaps` skips the caller `payload`).
- Credential exclusion: remote `token`/`certificate` held for the call only, never recorded, and used as redaction needles across message text, stacks, and error diagnostics (`:1059-1160`, `:1589-1614`). Doc: "Do not embed credentials in the endpoint address."
- Effects: `start_frida_session` = `{mutatesTarget, launchesProcess, accessesNetwork}`; `load/resume/close/instrument` add `executesForeignCode` (`toolEffects.ts:212-258`) -> all `destructiveHint: true`.

### 7. GDB and Rizin persistent debugger sessions (`src/gdb/`, `src/rizin/`, `src/process/PersistentDebuggerHost.ts`)
- `PersistentDebuggerHost.ts` is a 4-line predicate: persistent sessions are Linux-only because detach verification needs `/proc` descriptor readback; Windows is refused because owned Job Object cleanup "can terminate debugger inferiors" (`GdbSessionManager.ts:682`). macOS lacks the descriptor verification.
- GDB spawned `--nx --quiet --interpreter=mi3|mi2` through the owned provider process (`GdbSessionManager.ts:810`); commands run via `-interpreter-exec console <cmd>`. Startup disables auto-loading (rejected command aborts the session) and verifies a caller-selected `inferior_tty` before ready.
- `gdb_console` effects are the broadest in the codebase: `{mutatesTarget, writesFilesystem, launchesProcess, accessesNetwork, executesForeignCode, idempotent:false}` (`toolEffects.ts:77-93`). Evidence always carries the limitation "The unrestricted GDB console can access local shell, filesystem, network, and target controls." (`GdbSessionManager.ts:1301-1310`). Tool description repeats: "Commands can execute shell, alter target state, access files, and use network."
- Detach-proof machinery: commands that could change inferior output routing (`tty`, `set inferior-tty`, `run </>`, `source`, `define`, `py`) are classified and invalidate the TTY proof (`commandMayChangeInferiorOutput`, `:2403-2432`). Close detaches the single inferior only while a durable output sink is verified; multiple live inferiors force the caller to dispose of each explicitly (`:1498-1518`, `#detachInferior :1934-2007`).
- Rizin: spawned `-N -0 -d -R stdout=<tty> -R stderr=<tty> -e dbg.exitkills=false <path>` (`RizinDebugSessionManager.ts:437-453`). `dbg.exitkills=false` ensures closing Rizin does not kill the debuggee; detach verifies the ptrace FD via `olj` and that `dbg.exitkills` reads back false before release (`:1246-1363`). Rizin one-shot analysis (non-debug) uses `-N -q -e scr.color=0 -c <cmd>` (`RizinCommand.ts`). `rizin_debug_command` effects include `mayDiscardData` on top of the GDB-style set (`toolEffects.ts:94`). Session capacity is bounded; `start` reserves a slot before spawn.

### 8. Process capture + PTY (`src/application/process/`, `src/process/capture/`, `docs/process-capture.md`)
- `capture_process_scenario` runs one caller-selected command with the current user's permissions, inherits the host env plus explicit overrides. "This is not a sandbox." Effects = `{mutatesSession, writesFilesystem, launchesProcess, accessesNetwork, executesForeignCode, idempotent:false}` (`toolEffects.ts:740-748`).
- PTY wrapper: `@lydell/node-pty` 1.1.0 `spawn(executable, args, {cwd, env, cols, rows, name:"xterm-256color"})` (`src/process/capture/ProcessHarness.ts:293,333-339`). Why a PTY: to capture real terminal behavior (raw chunks, resizes, interactive input, signals) of CLI/TUI programs that only behave correctly on a tty. Linux/macOS only; native Windows capture is withheld because the PTY adapter cannot yet verify descendant cleanup.
- Terminal rendering: `@xterm/headless` 6.0.0 + `@xterm/addon-serialize` run headless at finalization to turn retained PTY chunks into deterministic rendered frames and `serialized_state` (`src/process/capture/TerminalRenderer.ts:11-60`); `allowProposedApi:true`, caller-selected scrollback; `columns x (rows+scrollback) <= 1,000,000`. This is the only place REA wraps a PTY + xterm, and it is purely for observation of an owned child, not for driving another app's terminal.
- Scenario can schedule timed `events`: `input` (optionally `sensitive` -> sent but persisted with empty data and only `input_bytes`), `resize`, `signal` (e.g. SIGINT). Filesystem observation paths snapshot `files_before/after`; "they do not restrict what the process can read or write."
- Kill/ownership: `REA_PROCESS_RUN_ID` injected into the child env (`ProviderProcess.ts:281`); finalization sends SIGTERM then at most one SIGKILL, each re-checking the retained start identity immediately before the call; `delivery` is `signaled/gone/identity-changed/unverified`; REA never falls back to a bare PID kill on failed identity (`ProcessCaptureLifecycle.ts:940-976`, `docs/process-capture.md`). Group signal via `process.kill(-pgid, signal)` only after token match (`ProcessOwnershipObservation.ts:1563`). Reserved env names `__proto__` and `REA_PROCESS_RUN_ID` are rejected as overrides.
- `compare_process_captures` is offline comparison of two Evidence files, available on Windows; it launches nothing.

### 9. Recorded signals and crashes (`docs/signal-recordings.md`, `docs/recorded-crashes.md`)
- `decode_signal_recording` / `inspect_signal_decoders`: run caller-supplied **sigrok-cli** on a private read-only copy of an existing recording, Linux-only, wrapped by `prlimit` (1 GiB AS, 64 MiB file, 30 CPU s, no core). It does not acquire samples or touch hardware. "These limits do not form an OS sandbox." Effects = `{mutatesSession, launchesProcess, writesFilesystem}`.
- `inspect_recorded_crash`: parse a caller core (ELF64) via pinned pwntools/pyelftools/Unicorn Python; optional GDB/pwndbg mapping context started with no initfiles/auto-load/debuginfod, `/proc/self/exe` placeholder, mapping-name path-traversal checks. "Historical PIDs are metadata. They never select a live process or authorize attach/control." These are **recordings**, not live interaction; INFER: the closest to "observe without touching a running target."

## How authority is declared to the agent (the mechanism worth borrowing)

- Single source of truth: `TOOL_EFFECTS: Record<string, ToolEffects>` audits every public tool; `toolContractMetadata(name)` throws if a tool has no audit (`toolEffects.ts:54,819`). Discovery (`binary_session`, catalog, `tools/list` annotations) and MCP hints all read from it.
- Derivation rule (`toolEffects.ts:765-786`): `readOnlyHint` = none of the mutate/launch/network/UI/discard/foreign/device flags set; `destructiveHint` = `mayDiscardData || executesForeignCode || mutatesDevice`; `openWorldHint` = `launchesProcess || accessesNetwork`; `idempotentHint = idempotent`. Note: running foreign code is destructive *by definition* even without data loss.
- Orthogonal taint flag: `TARGET_CONTENT_FREE_TOOLS` / `toolReturnsTargetContent(name)` marks whether a tool's output can carry attacker-controlled text; unknown/unaudited tools default to "returns target content" (fail-closed) (`toolEffects.ts:800-817`). Relevant for prompt-injection defense in a control plane.
- Prose descriptions restate the effect in caller-facing language and name the exact hazard ("never kills the target", "can execute shell, alter target state").

## Design choices that make it extensible

- Provider = one authority level. New runtime surfaces plug in as a provider with its own identity (`*ProviderIdentity.ts`), port interface (`*Port.ts` under `src/application/`), and composition factory (`src/composition/*.ts`). `createFridaInstrumentationProvider` is 3 lines and loads native bindings lazily.
- Shared `OwnedDebuggerDetachResult` / `ProviderProcessSupervisor` / ownership-token machinery (`src/process/`) is reused by GDB, Rizin, and process capture, so new launch/attach tools inherit the never-orphan guarantees.
- Shared `BrowserExclusionReason` vocabulary maps every denial across CDP, Playwright, Inspector, and Electron providers (`docs/browser-observation.md`).
- Capability gating is data: `persistentDebuggerHostSupported(platform)` and per-tool availability let a provider advertise "unavailable + reason + remediation" instead of failing opaquely (`docs/mcp-contracts.md` tool_availability).
- Evidence + `inspect_analysis_view` paging means a huge capture is retained server-side and streamed by view, so adding a new capture kind reuses summary/step/event/text paging.
- Declarative scenario schema (`browserScenarioSchema`) with a separate `validate-browser-scenario` command: the action vocabulary is a closed set validated before any process starts, and is the same for CLI and MCP.

## What to distill for an observe+drive control plane

- **Adopt the effect-vocabulary -> derived-hints pattern verbatim.** A control plane that both observes and drives needs a machine-checkable per-action record of `{mutatesTarget, writesFilesystem, launchesProcess, accessesNetwork, changesUiState, mayDiscardData, executesForeignCode, mutatesDevice, idempotent}` with an enforced "every action must be audited" invariant, and derive UI/consent hints from it rather than letting each action self-declare.
- **Separate authority tiers into distinct capabilities/endpoints**, as REA splits observe (attach + enable 2 domains) from instrument (coverage/listeners) from drive (scenario) from inject (Frida) from console (GDB). An agent can be granted a lower tier without the higher ones. The names themselves signal authority (`inspect_*` vs `capture_*_scenario` vs `*_console`).
- **Ownership token + identity-rechecked signaling** is the single most reusable safety primitive: tag every process you launch, and only ever signal/kill things that still carry your token and whose start identity still matches. Record `unverified` instead of guessing. This is exactly what a "drive" plane needs to avoid killing the user's unrelated processes on cleanup.
- **Default-deny external effects when you take over an app.** The Electron hook model (block shell-out, downloads, permission grants, non-loopback navigation; record everything else as shapes) is a template for driving a desktop app you do not fully trust while bounding blast radius.
- **Closed, declarative action vocabulary with pre-flight validation** beats arbitrary-command passthrough for the "drive" path; keep an explicit escape hatch (REA's `gdb_console`/Frida script) that is loudly flagged `executesForeignCode`/destructive and tier-gated.
- **Value-free observation by default**: capture shapes/structure/digests, redact secrets with forward-propagating markers, withhold pixels when secrets are in scope, exclude auth material from any durable record. A control plane's observation log is a data-exfiltration surface; REA treats it as one.
- **Taint tracking of outputs** (`returnsTargetContent`, fail-closed) lets the plane mark which observations are untrusted (page text, app output) before they reach the model.
- **Loopback-only, explicit-port, no-credential endpoint admission** and **refuse-if-already-attached** prevent the observe plane from being pointed at remote or shared targets.
- **Honest partial results and named, non-overridable budgets**: never let missing data read as "nothing happened"; always carry coverage + limitations + `partial_observation`.

## Constraints and risks (incl. the authorization boundary)

- REA repeatedly states none of these are sandboxes: process capture, signal decode, recorded crash, Electron active capture, and the GDB/Rizin consoles all run with the user's full privileges. A control plane cannot claim containment from lifecycle ownership alone.
- **No internal permission gate.** REA has "no permission grant step or per-call approval flag" and leans entirely on the MCP client's confirmation UI plus `rea setup` approval for config/install. An observe+drive plane that wants real gating must add it; REA's hints are advisory.
- The highest-authority tools (`gdb_console`, `rizin_debug_command`, Frida `load_script`/`instrument`, both scenario captures, process capture) are full foreign-code execution. They are the drive-plane analog and must be the most tightly gated; REA marks them destructive but does not restrict them.
- Authorization-boundary posture (relevant to agentic-anything's DRM/security line): DISCLAIMER/README/SECURITY scope REA to "software you own or are authorized to examine"; `AGENTS.md:7` requires a maintainer scope decision before any "target execution, injection, mutation, or protection recovery" capability. REA declines to bypass Electron fuses (fails `unsupported_target`), does not modify fuse bytes, does not install Frida server, uses ephemeral Ghidra DBs without modifying bytes, and keeps IDA read-only. INFER: the project's own line is "observe and even drive software you are authorized to, but do not defeat the target's protections" -- a good model for agentic-anything's stated non-goal of DRM/asset-extraction/security evasion.
- Cleanup fragility is documented, not solved: abrupt SIGKILL of REA orphans Playwright profiles (#4659); failed cleanup is retained for retry and blocks replacement work rather than being force-resolved; Linux `/proc/<pid>/environ` can be overwritten by Chromium so the run token is unreadable and lineage stays `unverified`.
- Platform asymmetry: persistent debuggers and process capture are Linux(/macOS) only; Windows is refused for stated lifecycle-safety reasons. A cross-platform control plane inherits this gap.
- Native-binding and tool trust: Frida bindings, sigrok, pwntools, GDB, the browser executable are all caller/BYO and trusted; hashes identify bytes, not publisher authenticity.
